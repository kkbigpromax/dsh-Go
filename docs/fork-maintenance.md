| 改动 | 保持的行为和检查位置 |
| --- | --- |

| 保留原生聊天，移除闲置功能 | 移除宠物、原版 DSH 网页界面、酒馆、伙伴小屋、左滑快捷面板、“帮助与关于”整组（使用帮助、社区、诊断、关于）。核查 `root_gate.dart`、`home_shell.dart`、设置页及索引、功能目录、深链、原生注册、Android manifest 和 `pubspec.yaml` 独占资源。参考 `0691376c`。 |

| 伙伴和诊断预设过滤 | `dsh-go-companion`、`dsh-go-companion-full`、`dsh-go-diagnostics` 不得出现在任何预设选择列表。共享规则位于 `app/lib/state/new_chat_modes.dart`；原始引擎目录保留用于识别旧默认值，首次发送前选用有效的保留预设，旧未完成设置恢复到标准模式。按稳定 ID 过滤，不误删用户自己创建的同名预设。参考 `513d469b` 和 `app/test/features/retired_presets_test.dart`。 |
| 关闭自更新 | 不自动检查或提示官方新版，隐藏检查更新及自动更新入口。用户自行编译和安装；现有更新框架可保留，不重新接入启动流程。参考 `3a4a739d`（曾限制为 fork）、`d3f2fcd4`（随后停用更新）。 |
| 保留核心能力与数据 | 保留原生聊天、引擎、本机/远程主机、语音、手机操控、聊天状态通知和内部错误捕获；保留用户现有会话、配置和运行时升级兼容性。不要按目录名批量删除共享模块。个人偏好、可视化回复、常规 Agent 预设继续保留。 |
| 版本、签名与交付 | 版本名称与本次合入的上游一致，不加 fork 后缀；内部构建号递增。仅本机构建并验证的 arm64 APK。重启后生成新固定证书，其后的新版沿用该证书。不自动发布 Release，也不下载线上包再上传。许可声明和必要署名继续保留。 |

当前移除的是 App 自身的统计和 DeepSeek 日志上传；没有承诺删除 Google ML Kit SDK 自身的统计行为。不要在维护或交付说明中扩大承诺。

## 每次合并必须做的两项检查

### 1. 检查并处理与我们改动的冲突

1. 核对干净的工作基线，记录上次已合入的上游提交与本次目标，比较两者之间的全部改动。
2. 检查 Git 文本冲突，也检查行为冲突：例如改名或新增调用后重新启动统计、恢复已移除功能、绕过预设过滤、改变签名或回退 debug 签名。Git 自动合并成功不表示兼容。
3. 逐项按上表核对源码、设置/搜索/菜单、旧偏好与草稿、启动监听、后台服务、独占依赖和资源；运行时补丁、pins 与生成包的真实内容也须一致。
4. 在保持用户需求的前提下处理冲突，采用最小必要改动；运行与受影响行为对应的测试和静态检查。无法确定功能取舍时，整理具体影响询问用户。

### 2. 检查上游是否新增其他功能

1. 对照源码与发布说明列出新增功能，包括默认关闭的功能、新入口、SDK、依赖、资源、权限、后台活动，以及改名后恢复的旧功能。
2. 对每个新功能用简短说明告知用户：用途、对当前用途的价值、额外负担（无法量化时注明未知）、是否容易独立排除，并询问是否加入。
3. 新功能须得到用户明确选择才加入；用户未决定时继续完成独立修复和冲突处理，暂不交付含该待定功能的 APK。不能把“合并上游”当成接受其所有新功能，也不能仅隐藏入口而保留它独有的负担。
4. 用户拒绝的功能按精简范围处理，并同步去掉相关设置与其他入口。现有共享依赖不能因为关联了被拒绝功能就误删。
5. 现有功能的漏洞修复、稳定性修复、兼容适配按原授权推进；同时增加能力或明显引入额外负担的部分须单独列出，不能借修复名义自动加入。

## 合并后更新记录与交付

- 更新本页上游基线、实际新增/保留/排除项、用户的新功能决定、冲突处理及验证结果，便于下一次准确比较。
- 核对 APK 架构、版本名、递增构建号、固定证书和运行时完整性。项目重启时按根目录 `AGENTS.md` 设置新固定签名。启用后如果密钥缺失或不符，停止构建并恢复当前启用的签名。
- 报告实际测试情况，区分静态检查、包内容检查和真机验证；未经手机验证不声称真机通过。
- 按用户授权推送改动并提供本机安装包，保持用户配置与会话；不创建未经要求的 PR、Tag 或 Release。
